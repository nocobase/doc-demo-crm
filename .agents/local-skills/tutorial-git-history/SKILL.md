# 按教程维护 Git 历史

本仓库是教程逐课演进的源码。以仓库根目录的相邻仓库 `../website-v3` 中的课程设计为准，所有提交、课程 Tags 和最新分支必须与课程内容及顺序一一对应。不能仅让最新代码正确，却留下与教程不符的历史版本。

## 课程来源与映射

- 阅读 `../website-v3/doc/content/zh-CN/guides/meta.json` 的课程导航及同一 `guides/` 目录下的课程正文；同时检查 `../website-v3/doc/content/guides/` 和其他语言的对应内容、源码链接及差异链接。顺序来自课程设计，不来自文件名排序、Tag 创建时间或现有 Git 历史。
- 当前起始映射为：`create-app.md` → `lesson-1`（创建和运行应用），`customers-and-follow-ups.md` → `lesson-2`（客户、联系人和跟进），`test-and-deliver.md` → `lesson-3`（测试和交付）。这只是现状，课程增删、拆分、合并或排序变化时必须重新推导完整映射，不能把三课写死。
- 实施前列出“课程顺序、课程文件、应有功能、提交、Tag”的对应表，并确认发布远端和最新分支；当前分支为 `main`，实际操作仍须检查 upstream 和远端配置。课程来源缺失或多语言课程设计冲突且无法判断时，先解决缺失信息，不能凭空编排历史。

## 历史修订原则

1. 教程有任意修改，或本仓库代码需要修改时，都先检查完整映射并确定最早受影响的课程。纯文字修改也要检查源码、命令、路径和链接是否仍然准确；确实无代码影响时不制造无意义代码差异。
2. 将修改归入首次需要它的课程提交，并依次重建受影响课程及全部后续提交。默认沿用当前“一课一个提交”的线性历史；不要在最终课程之后堆积修补提交、合并提交或无对应课程的提交。基础配置和仓库维护文件放入最早适用的课程阶段，不另造一课。
3. 每个阶段只包含到该课为止的内容。不能把最终代码复制到所有旧阶段，也不能让早期课程依赖后续课程才出现的文件、表、配置或功能。后续课程必须保留前序成果，除非教程明确要求替换或移除。
4. 必要时使用 amend、交互式 rebase 或按课重建提交，修正历史树、提交说明和父子关系。Git 没有“强制提交”选项；这里的要求是允许且需要改写已有提交，并在发布时强制更新远端引用。
5. 每次历史对齐发布都重新建立完整课程 Tag 集合，使各 Tag 精确指向对应课程完成提交，最新分支指向最后一课。删除或重命名课程时处理本地及远端的过期课程 Tags；无关引用不在操作范围内。
6. 修改教程中的旧 SHA、`tree`、`blob`、`compare` 链接及仓库说明中的阶段引用，使源码链接指向最终提交、差异链接比较相邻课程。检查所有语言，不能只更新中文。先固定提交，再填写最终 SHA，避免记录中间 SHA。编辑教程仓库前先读其 `AGENTS.md`。

## 执行与验证

- 检查两个仓库的工作区、提交图、分支、Tags 和远端状态。保护已有未提交工作，不擅自丢弃、混入提交或使用 `reset --hard` / `clean` 清理。重写前保存本地恢复引用或 Git bundle，并记录原分支与 Tag 对应的 SHA；备份不作为教程分支或 Tag 推送。
- 先完成可检查的课程映射和本地历史重建，再发布。只创建或修改此技能的请求不自动执行历史重写和推送；用户已授权的历史对齐发布包含强制推送，无须重复询问同一授权。
- 逐课检查提交树、相邻差异、运行说明和 Tag 指向。针对实际变化运行该阶段可用的测试；影响早期课程的变更需要验证后续受影响阶段。必要时使用隔离目录和数据库验证安装及跨课升级，不能因 Git 历史重建覆盖现有数据库。涉及历史迁移时明确区分教程快照与已运行数据库的迁移记录，并验证保留数据的升级路径。
- 验证课程数与课程 Tag 数一致、无漏课或重复映射，且 Tag 提交按课程顺序构成线性祖先链；最新分支 HEAD 等于最后一课的 Tag 提交。Git 的 Tag 列表显示顺序不代表课程顺序，应按教程映射和祖先关系检查。

## 强制发布

所有本仓库课程历史发布均采用强制更新：完整重打课程 Tags，并推送最新分支，不使用普通追加推送来掩盖历史不一致。

- 使用显式远端和引用列表，不使用 `--mirror`、`--all` 或会包含无关 Tags 的通配发布。分支默认使用带预期远端 SHA 的 `--force-with-lease=refs/heads/<branch>:<old-sha>`；它是强制推送，并能发现检查之后的并发变动。课程 Tags 使用显式的强制更新 refspec（`+refs/tags/<tag>:refs/tags/<tag>`）或等价的 `--force`。
- 支持时用一次 `git push --atomic` 发布最新分支及完整课程 Tag 更新/删除集合。远端不支持原子更新时，明确记录分步结果并核验全部目标引用，不能把部分成功报告为完成。
- 推送前再次检查远端引用。lease 拒绝或远端出现未评估的新提交时，先检查并纳入课程对齐，再重新发布；不能盲目重试覆盖。权限或受保护引用阻止强制更新时，报告具体阻碍，不绕过保护。
- 推送后通过 `git ls-remote` 核验最新分支和每个课程 Tag，带注释 Tag 同时核验其解引用后的提交。确认过期课程 Tags 已清除，教程链接使用最终 SHA。教程仓库自身的提交/发布遵循其规则和当前任务授权，本技能不授权强推教程仓库。
- 交付时列出最终“课程 → Tag → SHA”映射、最新分支、验证结果和推送状态；有任一课程、引用或教程链接未同步时明确说明，不能宣称已完全对齐。
